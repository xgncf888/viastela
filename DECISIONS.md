# Decisions

- One Expo application, not a monorepo, targets web, iOS, and Android.
- The client is Expo SDK 58, Expo Router, and react-native-web.
- The backend is Supabase Postgres with row level security and email OTP, and there is no second backend.
- Migrations are applied only via the Supabase connector after review, and local files are renamed to the hosted version afterwards.
- EAS Update uses the fingerprint `runtimeVersion` policy; preview and production channels are set in `eas.json`; week 1 does not run EAS builds.
- The display name, icon paths, URL scheme `viastela`, and store ids `com.viastela.app` live only in `src/config/brand.ts`.
- 2026-10-27: Yifeng decided directly (in chat with Grok Ultra) that the product is named Viastela; URL scheme `viastela`, iOS bundleIdentifier and Android package `com.viastela.app`. No personal ids in product identifiers.
- UI copy is Chinese.
- Routes live in `app/`, feature UI in `src/features/`, business rules in `src/core/`, Supabase calls in `src/data/`, and tokens plus shared components in `src/ui/`.
- ESLint rejects raw colors and raw sizes in `app/` and `src/features/`.
- Each record type has its own table; week 1 only creates `weight_records`.
- A weight row's id is a client-generated UUID, and a resubmit upserts that id.
- `local_day` is computed in `src/core` at write time from the record's IANA timezone and the user's day-switch, default `04:00`.
- Changing the day-switch or the device timezone does not rewrite stored `local_day` values.
- The 7-day average uses the earliest row of each `local_day` and divides by the number of days that have a row; later rows that day are notes.
- The 7-day average is insufficient data until 4 local days in the window have a weigh-in.
- The trend chart series is an exponential moving average (alpha 0.1) of the earliest weigh-in on each `local_day`. Days with no row are skipped and are not interpolated. The headline number stays the 7-day average.
- Weight list reads are the last 28 `local_day` values plus one latest row, and soft-deleted rows are excluded.
- A record row is removed by a plain update that sets `deleted_at`. Hard `DELETE` stays revoked. Keep `soft_delete_weight_record` until the app no longer calls it. Select policies check only `user_id = auth.uid()`, so a person can read their own deleted rows. The app adds `deleted_at is null` on every read through `liveRows`. `forbid_update_deleted` runs on every table with `deleted_at` and raises `P0001` with message `record deleted` when a deleted row is updated or upserted. The trigger is named so it sorts first (`weight_records_00_forbid_update_deleted`, `training_sets_00_forbid_update_deleted`) and that error wins over an invalid timezone. The app treats a row as deleted only when the code is `P0001` and the message is exactly `record deleted`. Any other error, including `P0001` with a different message and row-level security, is retried on the same id. The screen says `这条记录已在其他设备删除` and offers only 关闭. The raw error is not shown. A soft-delete update asks for `id` back; zero rows is a failed delete and the screen says `删除失败，请重试`.
- `training_sets` is one row per set. `weight_kg` and `band_level` are mutually exclusive. `band_level` is `light`, `medium`, `heavy`, or `extra_heavy`. The screen labels those 轻, 中, 重, 加重 and does not convert them to kilograms. `user_id` references `auth.users` on delete cascade. On insert, `assign_auth_user_id` sets `user_id` from `auth.uid()` and errors when that is null. On update it only keeps the previous `user_id` and does not check auth. `local_day` is frozen at write time.
- `local_day` must be the civil date of `recorded_at` in `tz` or the previous day. `weight_kg` stays inside (0, 500).
- `fixtures/local-day.json` is the shared vector file for the Jest local-day tests and the pgTAP trigger tests.
- Future money columns are integer minor units, a currency code, and an FX snapshot taken at write time.
- `expo-sqlite`, `expo-notifications`, `expo-localization`, and `react-native-svg` are dependencies before the first EAS dev build so adding offline storage, reminders, locale, or vector charts does not force a new native binary.
- Between 00:00 and the day-switch, the 今日 header and the save toast say which accounting date the entry uses, for example `已记入 10月23日`.
- Week 1 has no offline queue.
- CI on every push and pull request runs `tsc`, ESLint, Jest, pgTAP against the local Supabase stack, and a Playwright smoke test of the web export.
- The pre-push hook runs typecheck and Jest.
- 2026-10-27: Deleting an account calls the `delete-account` Edge Function. The function accepts only the caller's user JWT and deletes that auth user. Public `user_id` foreign keys are `on delete cascade`. The function reads `SUPABASE_SERVICE_ROLE_KEY` from the runtime environment. The value is not stored in the repo, the client, or CI logs. The function is not deployed from this repository.
- `backupPurgeDays` (30) is an upper bound for the account-deletion backup window: the longest published Supabase backup retention (Enterprise), not the retention of the current plan. `/privacy` and `/account/delete` both read that constant. Re-check the number if point-in-time recovery is enabled.
- The privacy policy lists weight, training sets, study records, and the account email, display name, and avatar from Google or GitHub. Training and study tables arrive in later pull requests of this release. The policy says the data is not sold, ads are not shown, and data is not sent to an AI service. The profile setting today is only the day switch (日切时间). CORS tightening and a recent-login check before deletion wait until before the external beta.
- Before shipping any AI feature, the privacy policy's "not sent to AI services" paragraph must be updated first.
- Sign-in methods are email OTP, Google, and GitHub. The same verified email is one account only when each sign-in method supplies that email. A GitHub primary email that differs from the login email is a separate account. Web sign-in starts Google or GitHub with `signInWithOAuth` and returns to the current origin. No provider secret is stored in the repo.
- Google and GitHub buttons render only on web (`Platform.OS === 'web'`). Native OAuth is a later task: `WebBrowser.openAuthSessionAsync`, then `exchangeCodeForSession`, with redirect `viastela://auth/callback`. Sign in with Apple is required before the iOS release.
- 删除账号 is the last control on 我的, 24px under 退出登录, as danger-colored ghost text. The confirm button on the deletion page uses the solid `danger` variant.
